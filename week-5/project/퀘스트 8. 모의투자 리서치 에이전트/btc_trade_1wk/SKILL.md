# BTC_trade_1wk — 규칙 기반 1주일 모의매매

사용자가 정한 **고정된 매매 규칙**을 지난 1주일의 1시간봉에 봉 하나씩 적용해
"이 규칙대로 했으면 어땠는지"와 "지금 봉에서 규칙이 무엇을 말하는지"를 보여준다.
판단을 새로 만들지 않고, **규칙을 그대로 집행한 결과만** 보고한다.

## 작업 폴더

```
week-5/project/퀘스트 8. 모의투자 리서치 에이전트/
```

아래 경로는 전부 이 폴더 기준이다.

| 파일 | 역할 |
|---|---|
| `BTC_trade_1wk.md` | 규칙 원문과 해석 (원본은 `BTC_trade_1wk.docx`) |
| `lib/rule-trade.js` | 규칙과 모의매매 계산 (시작 현금 `START_CASH`, 매수 비율 `BUY_RATIO`) |
| `scripts/trade-1wk.js` | CLI — 업비트 1시간봉을 받아 모의매매하고 일지를 저장 |
| `server.js` · `index.html` | 차트 앱(3100) — 「규칙 모의매매 현황」 패널과 차트 위 매수·매도 포인트 |
| `lib/upbit.js` | 업비트 캔들 수집과 이동평균 계산 (paper-trade 스킬과 공유) |
| `journal/BTC_trade_1wk_YYYY-MM-DD.md` | 실행 결과 |

## 규칙 (1시간봉 종가 기준)

| 규칙 | 조건 | 주문 |
|---|---|---|
| 매수 | MA20 > MA120 그리고 MA4 < 종가 < MA20 | 보유 현금의 3% |
| 매도① | MA4×MA20 데드크로스 후(MA4 < MA20) 종가 > MA4 | 보유 수량의 50% (데드크로스 1회당 1번) |
| 매도② | MA20×MA120 데드크로스 후(MA20 < MA120) 종가 > MA20 | 보유 수량 전량 |

같은 봉에서 매도와 매수가 겹치면 매도가 우선이다. 해석의 근거는 `BTC_trade_1wk.md`에 있다.
**규칙을 바꿔 달라는 요청이 아니면 규칙을 임의로 고치지 않는다.**

## 1단계 — 실행

```bash
cd "week-5/project/퀘스트 8. 모의투자 리서치 에이전트"
node scripts/trade-1wk.js
```

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--cash N` | 10000000 | 시작 현금(원) |
| `--days N` | 7 | 기간(일). 1시간봉 N×24개 |
| `--no-save` | | 일지 파일을 만들지 않고 콘솔 요약만 |

사용자가 week-4 모의투자 계좌 기준으로 보고 싶어 하면
`curl -s http://localhost:3000/api/portfolio`로 현금을 확인해 `--cash`에 넣는다.

의존성은 없다(Node 18+ 내장 `fetch`). 업비트 공개 시세라 API 키도 필요 없다.

화면으로 보려면 `node server.js` 후 http://localhost:3100 — 「규칙 모의매매 현황」에
평가자산·수익률·현금·보유 BTC·평가/실현손익이 나오고, 차트에 매수(빨강 ▲)·매도①(파랑 ▼)·
매도②(보라 ▼) 포인트가 찍힌다(1시간봉 보기에서만). API는 `GET /api/rule-trade?days=7`.

## 2단계 — 결과 확인

콘솔 요약 여섯 줄과 저장된 `journal/BTC_trade_1wk_YYYY-MM-DD.md`를 읽는다. 일지에는
결과 표, 체결 내역 전체, 마지막 완성 봉의 조건별 참/거짓이 들어 있다.

## 3단계 — 사용자에게 보고

- **결과 한 줄:** 시작 현금 → 평가자산(수익률), 같은 기간 단순보유 수익률
- **체결 횟수:** 매수 / 매도① / 매도② 몇 번, 수수료 합계
- **지금 규칙 판정:** 마지막 완성 봉에서 매수·매도①·매도②·대기 중 무엇인지, 어느 조건이 막고 있는지
- **눈에 띄는 점:** 규칙이 잘 맞았거나 어긋난 구간 한두 개 (예: "상승장에서 3%씩만 사서 단순보유보다 크게 뒤처짐")
- **저장한 파일 경로**

캔들 데이터를 채팅에 쏟아붓지 않는다. 체결 내역이 길면 일지로 안내한다.

## 하지 않는 것

- **실제 주문을 넣지 않는다.** week-4 모의투자 앱에 주문을 넣는 것도 사용자가 명시적으로
  지시했을 때만 하고, 그 절차는 `paper-trade` 스킬의 5단계를 따른다.
- **진행 중인 봉으로 판정하지 않는다.** 스크립트가 마지막 봉을 자동으로 뺀다.
- 결과를 투자 조언처럼 쓰지 않는다. 모의투자 연습용 기록이다.
