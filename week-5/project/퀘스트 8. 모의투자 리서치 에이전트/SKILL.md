# 모의투자 리서치 에이전트 (KRW-BTC)

업비트 실시간 시세로 **이동평균선을 그리고 → 지금 위치를 읽고 → 모의투자 계좌와 대조해
판단을 남기는** 것까지가 한 번의 작업이다. 주문은 사용자가 승인할 때만 넣는다.

## 작업 폴더

```
week-5/project/퀘스트 8. 모의투자 리서치 에이전트/
```

이 스킬의 모든 입출력은 위 폴더 안에서 이뤄진다. 아래 경로는 전부 이 폴더 기준이다.

| 파일 | 역할 |
|---|---|
| `lib/upbit.js` | 업비트 캔들·시세 수집과 이동평균·신호 계산 (의존성 없음) |
| `scripts/fetch-candles.js` | 스냅샷 CLI — `data/` 에 JSON 저장 + 요약 출력 |
| `server.js` | 차트 서버 (기본 3100). 업비트 호출과 지갑 조회를 서버가 대신 한다 |
| `index.html` | 캔들 + MA4/MA20/MA120 차트 화면 |
| `data/` | 수집 스냅샷 (`latest.json` 은 항상 최신) |
| `journal/` | 매매일지 `YYYY-MM-DD.md` |

**연동 대상**: week-4 `퀘스트 1. 나만의 모의투자 앱` (기본 `http://localhost:3000`).
지갑·주문은 전부 그 앱의 API 를 통해서만 읽고 쓴다. **이 스킬은 DB 에 직접 접속하지 않는다.**

## 1단계 — 시세와 이동평균을 받는다

```bash
cd "week-5/project/퀘스트 8. 모의투자 리서치 에이전트"
node scripts/fetch-candles.js                          # KRW-BTC 1시간봉 200봉, MA4/MA20/MA120
node scripts/fetch-candles.js --count 400              # 더 긴 구간
node scripts/fetch-candles.js --unit day --ma 4,20,120 # 일봉 4/20/120일선
```

출력에 판단에 필요한 값이 다 들어 있다 — 현재가, **세 선의 값·이격도·기울기**,
**정배열/역배열/혼조**, 그리고 교차 두 가지:

- **추세 교차** = 가장 긴 두 선(MA20 × MA120) — 추세가 바뀐 자리
- **단기 교차** = 가장 짧은 두 선(MA4 × MA20) — 진입·청산 타이밍 자리

원본은 `data/latest.json` 에 남으므로 일지를 쓸 때 다시 읽으면 된다.
`--ma` 로 기간을 바꾸면 이 역할 배정도 자동으로 따라간다 (선이 둘뿐이면 단기 교차는 없다).

### 기간을 세는 단위

**MA 기간은 "봉 개수"로 센다.** 1시간봉 기준 MA120은 최근 **120시간(5일)**,
MA20은 **20시간**, MA4는 **4시간**이다.
사용자가 말하는 "120일선"이 **일봉 기준 120일**을 뜻할 수도 있으므로, 판단이 갈릴 만한
자리에서는 `--unit day` 로 한 번 더 뽑아 두 기준을 같이 본다
(차트 화면에서는 「같은 기간 일봉선 겹치기」 체크박스가 같은 일을 한다).

### 업비트 API 를 브라우저에서 직접 부르지 않는다

캔들·시세는 인증이 필요 없지만, 호출은 항상 `lib/upbit.js`(서버 쪽)를 거친다.
한 번에 최대 200봉만 주므로 `to` 파라미터로 과거 쪽으로 이어 받고, MA120을 200봉 전부에
채우려면 319봉이 필요하다 — 이 페이징은 `buildSeries()` 가 이미 처리한다.

## 2단계 — 차트를 띄운다

```bash
node server.js          # http://localhost:3100
```

- 캔들 + **MA4(하늘)** + **MA20(노랑)** + **MA120(보라)** + 거래량,
  상단에 실시간 현재가(5초)와 봉 갱신(30초).
- 하단 카드: 선마다 한 장(값·이격·기울기) + 배열 + 추세 교차 + 단기 교차.
- `MA` 입력칸에 `4,20,120` 처럼 쉼표로 적으면 선을 늘리거나 줄일 수 있다.
- week-4 앱이 떠 있으면 **평균 매수가가 초록 점선으로 차트에 그려진다.** 꺼져 있어도 차트는 동작한다.
- 봉 단위(15분·1시간·4시간·일), 봉 개수, MA 기간은 화면에서 바꿀 수 있다.

사용자가 "보여줘"라고 하면 링크를 주고, **화면 캡처가 필요하면** Playwright 로
`http://localhost:3100/` 을 열어 스크린샷을 찍어 퀘스트 폴더에 저장한다.

## 3단계 — 내 계좌 위치를 확인한다

```bash
curl -s http://localhost:3000/api/portfolio
```

현금 / 보유 수량 / 평단 / 실현손익, 그리고 최근 주문 목록이 한 번에 온다.
**평단과 MA선의 위치 관계**가 핵심이다 — 평단이 MA120 아래인지 위인지에 따라 같은 신호도 뜻이 달라진다.

## 4단계 — 판단한다

**세 선은 역할이 다르다.** MA120은 추세의 바닥, MA20은 추세의 허리, MA4는 지금 이 순간이다.
**큰 방향은 MA20×MA120 으로 정하고, 들어갈 자리만 MA4 로 고른다.**
MA4 혼자로는 방향을 정하지 않는다 — 4시간 평균이라 하루에도 여러 번 뒤집힌다.

| 상태 | 읽는 법 | 기본 대응 |
|---|---|---|
| 정배열 + 현재가 모든 선 위 | 상승 추세 유지 | 보유 유지. 신규 진입은 MA4가 MA20까지 눌릴 때 |
| 정배열 + MA4가 MA20 아래로 | 추세 중 눌림 | 분할 매수 후보. MA120 이탈 시 철회 |
| 정배열인데 MA4만 급하게 벌어짐 | 단기 과열 | 추격 금지. MA4 이격 ±3% 넘으면 되돌림 대기 |
| 역배열 + 현재가 모든 선 아래 | 하락 추세 | 관망. 물타기 금지 |
| 역배열인데 MA4가 MA20 위로 | 반등 시도 | MA20×MA120 골든크로스 확인 전까지 관망 |
| 교차 3봉 이내 | 신호 발생 직후 | 되돌림이 잦다. 한 봉 마감을 더 보고 판단 |
| 혼조 (선 순서가 뒤섞임) | 방향 없음 | 판단 보류. 배열이 정리될 때까지 기다린다 |

같이 봐야 할 것:

- **이격도.** MA20 이격이 **±3%** 를 넘으면 단기 과열·과매도로 보고 추격하지 않는다.
  MA4 이격은 원래 작다(보통 ±1% 안쪽) — 이 값이 커졌다면 방금 급변했다는 뜻이다.
- **기울기.** 크로스가 났어도 MA120 기울기가 반대면 신호의 힘이 약하다.
- **단기 교차는 잦다.** MA4×MA20 골든크로스는 하루에도 몇 번씩 난다.
  **추세(MA20×MA120)와 같은 방향일 때만** 매매 근거로 쓴다.
- **마지막 봉은 미완성**이다. 진행 중인 봉의 종가로 크로스를 확정하지 않는다.
- **수수료 왕복 0.1%.** week-4 기록을 보면 이틀간 가격 차익의 94%를 수수료로 냈다.
  0.1% 미만을 노리는 매매는 그 자체로 손실이므로 권하지 않는다.

**판단은 근거와 숫자로 쓴다.** "오를 것 같다"가 아니라
"정배열 유지, MA20 이격 +0.4%로 과열 아님, 75봉 전 골든크로스 이후 MA120 기울기 +0.8%" 처럼 쓴다.

## 5단계 — 주문은 사용자 승인 후에만

에이전트가 스스로 주문을 넣지 않는다. 사용자가 명시적으로 지시했을 때만,
**수량·예상 금액·수수료·체결 후 잔고를 먼저 보여주고** 확인을 받은 뒤 week-4 앱에 넣는다.

```bash
curl -s -X POST http://localhost:3000/api/orders \
  -H "content-type: application/json" \
  -d '{"side":"buy","amount":300000,"memo":"1시간봉 MA20 눌림 매수"}'
```

- 매수는 `amount`(원) 또는 `qty`, 매도는 `qty`.
- 체결가는 **서버가 업비트에서 직접 조회한 값**이다. 클라이언트가 가격을 정하지 않는다.
- `memo` 에는 **왜 샀는지(어떤 신호인지)** 를 남긴다. 일지를 쓸 때 이 메모가 근거가 된다.

## 6단계 — 일지를 남긴다

`journal/YYYY-MM-DD.md` 에 그날의 판단을 남긴다. 형식은 week-4
`퀘스트 2. 매매 기록` 의 매매기록 md 를 따른다.

1. **한눈에 보기** 표 — 현재가, MA4/MA20/MA120, 이격, 배열, 추세·단기 교차, 계좌 상태
2. **오늘의 판단과 근거** — 위 표의 어느 칸이었고 무엇을 했는지(또는 왜 안 했는지)
3. **체결 내역** — 있으면 시각·수량·체결가·수수료·실현손익
4. **다음에 볼 것** — 어떤 값이 어떻게 되면 생각을 바꿀지 (예: "MA120 107.4M 이탈 시 관망 전환")

판단을 바꾼 날은 **왜 바꿨는지**를 반드시 적는다. 그래야 일지가 성적표가 아니라 근거의 기록이 된다.
