# Glaucoma 주간 리서치 (최근 1주일)

관심 분야의 지난 1주일 신규 논문을 PubMed에서 모아, 그냥 나열하는 목록이 아니라
**"이번 주에 무슨 일이 있었는지"를 읽히게 쓴 한글 리포트**로 만든다.

## 작업 폴더

```
week-5/project/퀘스트 5. 관심분야 자동 리서치 스킬 만들기/
```

이 스킬의 모든 입출력은 위 폴더 안에서 이뤄진다. 아래 경로는 전부 이 폴더 기준이다.

## 기본 설정

| 항목 | 기본값 |
|---|---|
| 키워드 | `glaucoma` |
| 검색 필드 | `[Title/Abstract]` |
| 기간 | 최근 7일 (PubMed 등재일 `EDAT` 기준) |
| 실행 주기 | 매주 금요일 |
| 리포트 | `reports/YYYY-MM-DD_<키워드>_weekly.md` |
| 원본 데이터 | `data/YYYY-MM-DD_<키워드>_papers.json`, `..._medline.txt` |

사용자가 다른 키워드나 기간을 말하면 그걸 따른다.

---

## 1단계 — 수집

### PubMed 웹사이트를 브라우저로 긁지 않는다

`https://pubmed.ncbi.nlm.nih.gov/?term=...` 를 Playwright로 열면 검색 결과 대신
**reCAPTCHA "브라우저 확인 중" 페이지**가 뜬다. NCBI가 자동화 트래픽을 막고 있어서
브라우저 경로로는 결과를 얻을 수 없다. 우회하지 말고,
NCBI가 프로그램 접근용으로 공개한 **E-utilities API**를 쓴다.

```bash
cd "week-5/project/퀘스트 5. 관심분야 자동 리서치 스킬 만들기"
node scripts/fetch-pubmed.js --keyword glaucoma --days 7 --out data
```

기간을 직접 지정하려면 `--from 2026/09/14 --to 2026/09/20` 를 쓴다.

스크립트는 `esearch.fcgi` 로 조건에 맞는 PMID를 받고, `efetch.fcgi` 로 그 PMID들의
MEDLINE 레코드를 POST로 한 번에 받아 제목·초록·저널·발행일·논문유형·저자·MeSH·DOI를
JSON으로 저장한다. 의존성 없이 Node 내장 fetch만 쓴다.

**매주 금요일 08:00**에는 Windows 작업 스케줄러의 `PubMed Weekly - glaucoma` 작업이
`scripts/run-weekly.cmd` 를 실행해 직전 7일치를 미리 받아 둔다. 그러므로
**오늘 날짜의 JSON이 `data/` 에 이미 있으면 다시 받지 말고 그 파일을 읽어 2단계로 넘어간다.**
파일이 없거나 사용자가 다른 기간·키워드를 말하면 새로 수집한다.

### 날짜는 `EDAT`으로 거른다

PubMed의 날짜 필드는 여러 개다. `DP`(발행일)는 저널마다 "2026 Oct", "2026 Fall" 처럼
제각각이고 온라인 선공개와 지면 발행이 몇 달씩 벌어진다. 주간 리서치에서 알고 싶은 건
**"이번 주에 새로 볼 수 있게 된 논문"** 이므로 PubMed 등재일인 `EDAT`으로 거른다.

### API 키는 환경변수로만

`NCBI_API_KEY` 환경변수가 있으면 스크립트가 자동으로 붙여 rate limit을 초당 3회에서
10회로 올린다. 키는 선택 사항이며, **코드·리포트·커밋에 키 문자열을 적지 않는다.**

## 2단계 — 전부 읽기

저장된 JSON의 **모든 논문의 제목과 초록을 실제로 읽는다.**

제목만 보고 분류하면 반드시 틀린다. `glaucoma[Title/Abstract]` 로 잡힌 논문 중 상당수는
녹내장이 **주제가 아니라 배경**으로 언급된 것이다. 90대 백내장수술 논문, 소아 포도막염
역학 논문, 난소암 약물의 FAERS 분석까지 함께 걸린다.

편수가 많아 출력이 잘리면 **잘린 부분을 이어서 읽고, 몇 편까지 읽었는지 확인한다.**
전부 읽지 못했다면 요약하기 전에 그 사실을 밝힌다.

---

## 3단계 — 주제별로 묶기

고정된 분류표를 강요하지 말고 **그 주에 실제로 모인 논문에 맞춰** 묶는다.
녹내장이면 보통 이런 축으로 나뉜다.

- 수술·시술 (MIGS, 유출장치, 여과수술, 레이저)
- 약물 치료와 약물 전달
- 진단·영상·인공지능
- 유전학·분자 기전·기초 연구
- 역학·보건의료·환자 경험
- 증례보고와 감별진단

각 묶음에 **몇 편인지** 적고, 편수가 가장 많은 주제를 맨 앞에 둔다.
같은 기기·약물·주제가 한 주에 **3편 이상 몰리면 그 자체가 신호**이므로 표로 모아 보여준다.

---

## 4단계 — 리포트 쓰기

읽는 사람은 이 분야를 아는 임상의·연구자다. 용어를 풀어 설명하지 말고,
**무엇이 새로운지와 왜 중요한지**에 지면을 쓴다.

지켜야 할 것:

- **숫자를 넣는다.** "IOP가 감소했다"가 아니라 "24.0 → 12.5 mmHg (p<0.001), 81안".
  표본 수, 신뢰구간, 추적 기간을 초록에서 찾아 그대로 쓴다.
- **모든 논문에 PubMed 링크를 단다.** `[PMID](https://pubmed.ncbi.nlm.nih.gov/PMID/)` 형식.
- **음성 결과와 반대 증거를 빼지 않는다.** "연관이 없었다"는 결과도 그 자체로 정보다.
- **초록에 없는 내용을 지어내지 않는다.** 초록이 없는 논문(서신·사설 등)은
  제목만 있다는 점을 드러내고 제목 수준에서만 언급한다.
- **맨 위에 「한 줄 요약」**, **맨 아래에 「이번 주 꼭 읽을 5편」** 표를 둔다.
  5편은 편수가 많은 순이 아니라 **임상이나 연구 방향을 실제로 바꿀 수 있는 순**으로 고르고,
  고른 이유를 한 줄씩 적는다.
- 여러 논문이 같은 임상 메시지를 가리키면 인용부호 블록(`>`)으로 그 메시지를 따로 적는다.
  (예: 같은 주에 독립적으로 보고된 두 증례가 같은 감별진단을 가리키는 경우)
- 맨 끝에 **검색 재현 방법**(esearch·efetch 명령)을 남겨 다음 주와 비교할 수 있게 한다.

## 참고: 주간 자동 수집 작업 관리

```powershell
# 상태 확인
Get-ScheduledTaskInfo -TaskName "PubMed Weekly - glaucoma" |
  Select-Object LastRunTime, LastTaskResult, NextRunTime

# 지금 바로 한 번 실행
Start-ScheduledTask -TaskName "PubMed Weekly - glaucoma"

# 등록 해제
Unregister-ScheduledTask -TaskName "PubMed Weekly - glaucoma" -Confirm:$false
```

로그는 `logs/run-weekly.log` 이고 UTF-8이므로, PowerShell에서 볼 때는
`Get-Content ... -Encoding utf8` 을 붙인다. 붙이지 않으면 한글이 깨져 보인다
(파일이 깨진 게 아니라 읽는 쪽 문제다).

`run-weekly.cmd` 를 고칠 일이 생기면 **본문에 한글을 넣지 않는다.** cmd.exe는 배치 파일을
시스템 ANSI 코드페이지(한국어 Windows는 CP949)로 한 줄씩 파싱하므로, UTF-8 한글이 들어가면
`REM` 주석줄까지 명령어로 쪼개지면서 작업이 조용히 실패한다
(작업 스케줄러는 `LastTaskResult 0`, 즉 성공을 반환한다).
