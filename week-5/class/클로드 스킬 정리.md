# 클로드 스킬(Agent Skills) 정리

> 작성일: 2026-09-15 · 참고: Claude Code 공식 문서(code.claude.com/docs/en/skills), Claude Platform Agent Skills 문서

---

## 1. 스킬이란?

**스킬(Skill)은 Claude에게 특정 작업을 하는 방법을 가르쳐 두는 "업무 매뉴얼 폴더"다.**
폴더 하나에 `SKILL.md`(지시문)를 넣고, 필요하면 스크립트·템플릿·참고 문서를 함께 둔다.
Claude는 사용자의 요청이 스킬 설명과 맞으면 알아서 그 매뉴얼을 꺼내 읽고 그대로 따른다.

이런 상황이면 스킬로 만들 때가 된 것이다.

- 같은 지시를 채팅에 **몇 번이고 다시 붙여넣고** 있을 때
- `CLAUDE.md`의 한 부분이 **여러 단계짜리 절차**로 커졌을 때
- 팀원 모두가 **같은 방식으로** 반복 작업을 처리해야 할 때

---

## 2. 핵심 원리: 점진적 공개(Progressive Disclosure)

스킬을 많이 설치해도 대화가 무거워지지 않는 이유는 **필요한 만큼만 단계적으로 읽기** 때문이다.

| 단계 | 무엇을 읽나 | 언제 | 비용 |
| --- | --- | --- | --- |
| 1. 메타데이터 | `name`, `description` | 세션 시작 시 항상 | 스킬당 약 100 토큰 |
| 2. 본문 | `SKILL.md` 본문 | 요청이 설명과 맞아 스킬이 호출될 때 | 보통 5,000 토큰 이하 권장 |
| 3. 리소스 | `reference.md`, `scripts/`, 데이터 파일 | 본문이 가리키고 실제로 필요할 때 | 열기 전까지 0 |

즉 Claude는 평소에 스킬의 **목차(이름+설명)** 만 들고 있다가, 해당 작업이 들어오면 그때 본문을 펼친다.
그래서 **`description`을 잘 쓰는 것이 스킬 품질의 절반**이다.

---

## 3. 폴더 구조와 SKILL.md 형식

```
my-skill/
├── SKILL.md          ← 필수. 첫 줄은 반드시 ---
├── reference.md      ← 선택: 자세한 참고 자료
├── examples.md       ← 선택: 예시
└── scripts/
    └── helper.sh     ← 선택: 실행할 스크립트
```

### SKILL.md 기본 모양

```markdown
---
name: whisper
description: 음성·영상 파일(mp3/m4a/mp4/wav)을 OpenAI Whisper API로 받아써서 transcript.md로 만들 때 사용. "이 음성 받아써줘", "회의 녹음 정리" 같은 요청에 사용.
---

# Whisper 받아쓰기

## 1. 작업 절차
1. 파일 크기 확인 — 25MB 이하면 바로, 넘으면 잘라서 보낸다
2. whisper-1 모델, language=ko 로 요청
3. 결과를 transcript.md 로 저장
```

> ⚠️ 여는 `---`가 **파일의 맨 첫 줄**이 아니면 frontmatter로 인식되지 않고 전체가 그냥 본문 취급된다.

### 자주 쓰는 frontmatter 필드 (Claude Code 기준)

| 필드 | 의미 |
| --- | --- |
| `name` | 스킬 이름. 소문자·숫자·하이픈, 최대 64자. 생략하면 폴더 이름을 쓴다 |
| `description` | **무엇을 하고, 언제 쓰는지.** Claude가 자동 호출 여부를 이걸로 판단한다 |
| `when_to_use` | 추가 트리거 문구(예시 요청, 동의어). description 뒤에 붙는다 |
| `argument-hint` | `/스킬명` 입력 시 보이는 인자 힌트. 예: `[issue-number]` |
| `arguments` | 이름 붙은 인자 목록. 본문에서 `$name`으로 사용 |
| `disable-model-invocation` | `true`면 **사용자만** `/스킬명`으로 실행 가능 (배포·커밋처럼 부작용 있는 작업용) |
| `user-invocable` | `false`면 **Claude만** 호출 가능 (배경지식용 스킬) |
| `allowed-tools` | 스킬 실행 중 권한 확인 없이 쓸 수 있는 도구. 예: `Bash(git *), Read` |
| `disallowed-tools` | 스킬 실행 중 쓰지 못하게 막을 도구 |
| `model` / `effort` | 스킬 실행 시 사용할 모델·추론 강도 지정 |
| `context: fork` | 대화 기록과 분리된 **서브에이전트**에서 실행 |
| `agent` | `context: fork`일 때 쓸 에이전트 종류 (`Explore`, `Plan`, 커스텀 에이전트 등) |
| `paths` | 특정 파일(glob)을 다룰 때만 자동 호출되게 제한. 예: `["*.py"]` |
| `hooks` | 스킬이 호출될 때 등록할 훅 |

> 모든 필드가 선택이지만, **`description`은 사실상 필수**다(API 업로드 시에는 `name`·`description` 필수).
> description + when_to_use 합계는 1,536자까지 목록에 표시된다.

## 4. 스킬은 어디에 두나?

| 범위 | 경로 | 적용 대상 |
| --- | --- | --- |
| 엔터프라이즈 | 관리자 배포 설정 | 조직 전체 |
| 개인 | `~/.claude/skills/<이름>/` | 내 컴퓨터의 모든 프로젝트 |
| 프로젝트 | `.claude/skills/<이름>/` | 이 저장소 (git으로 팀과 공유 가능) |
| 하위 폴더 | `<하위폴더>/.claude/skills/<이름>/` | 모노레포의 해당 폴더 작업 시 |
| 플러그인 | `<플러그인>/skills/<이름>/` | `/플러그인명:스킬명` 으로 네임스페이스 분리 |

- 이름이 겹치면 **엔터프라이즈 > 개인 > 프로젝트 > 기본 내장** 순으로 우선한다.
- 세션 중 `SKILL.md`를 고치면 바로 반영된다. 단, **새 스킬 폴더를 처음 만들었다면 Claude Code를 재시작**해야 인식하는 경우가 있다.

> 📌 이 저장소는 `.claude/`가 `.gitignore`에 들어 있어서, `.claude/skills/`에만 둔 스킬은 커밋되지 않는다.
> 과제 제출용이면 퀘스트 폴더에 사본(예: `week-4/project/퀘스트 3. …/SKILL.md`)을 함께 둔다.

## 5. 스킬을 실행하는 두 가지 방법

### ① 자동 호출
사용자가 "이 유튜브 자막 받아줘"라고 말하면, Claude가 설치된 스킬들의 description과 비교해 `yt-dlp` 스킬을 스스로 불러온다.

### ② 직접 호출 (슬래시 명령)
```
/recipe
/fix-issue 123
```
**스킬 = 슬래시 명령**이다. 예전 `.claude/commands/deploy.md` 방식도 계속 동작하지만, 지금은 스킬로 만드는 것이 기본이다.

### 본문에서 쓸 수 있는 치환 문법

| 문법 | 의미 |
| --- | --- |
| `$ARGUMENTS` | 넘겨받은 인자 전체 |
| `$0`, `$1` … / `$ARGUMENTS[0]` | N번째 인자 (0부터) |
| `$name` | `arguments`에 정의한 이름 인자 |
| `${CLAUDE_SKILL_DIR}` | 스킬 폴더의 실제 경로 (스크립트 호출할 때 유용) |
| `${CLAUDE_PROJECT_DIR}` | 프로젝트 루트 경로 |
| `${CLAUDE_SESSION_ID}` | 현재 세션 ID |

### 동적 컨텍스트 주입
본문에 `` !`명령어` ``를 쓰면, Claude가 스킬을 읽기 **전에** 명령이 실행되고 그 결과가 그 자리에 들어간다.

````markdown
현재 브랜치: !`git branch --show-current`
변경 파일:
```!
git status --short
```
````

- 명령마다 2분 제한, 실패(0이 아닌 종료 코드)하면 스킬 호출 자체가 실패한다.

## 6. 스킬 vs 비슷한 기능 비교

| 기능 | 언제 로드되나 | 무엇에 쓰나 |
| --- | --- | --- |
| **CLAUDE.md** | 모든 세션에 항상 | 모든 대화에 적용되는 규칙 (폴더 규칙, 코드 스타일) |
| **스킬** | 필요할 때만 | 가끔 쓰는 절차·전문 지식 (받아쓰기, 문서 변환, 배포) |
| **서브에이전트** | 위임할 때 | 독립된 컨텍스트에서 따로 일하는 작업자 |
| **MCP 서버** | 계속 연결 | 외부 도구·API·DB 연결 (예: Playwright 브라우저 조작) |
| **플러그인** | 설치 시 | 스킬·MCP·훅·에이전트를 한 묶음으로 배포하는 포장 |

한 줄 요약: **CLAUDE.md는 "항상 지킬 규칙", 스킬은 "필요할 때 펼치는 매뉴얼", MCP는 "손에 쥐여 주는 도구".**
스킬 안에서 MCP 도구나 스크립트를 쓰라고 지시하는 식으로 조합해 쓴다.

## 7. Claude Code 밖에서의 스킬

| 환경 | 사용 방법 |
| --- | --- |
| **Claude.ai / 데스크톱 앱** | 기본 제공 스킬(Word·Excel·PowerPoint·PDF) 사용 가능. 직접 만든 스킬은 설정에서 zip으로 업로드 (유료 플랜 + 코드 실행 기능 필요) |
| **Claude API** | Messages API의 `container` 파라미터에 스킬을 지정하고 코드 실행 도구와 함께 사용. 커스텀 스킬은 `/v1/skills` 엔드포인트로 업로드. 샌드박스라 **네트워크 접속·패키지 설치 불가** |
| **Agent SDK** | 자체 에이전트 앱에서 `.claude/skills/` 파일 시스템 스킬을 불러와 사용 |

### 기본 제공(Anthropic) 스킬
- `docx` — Word 문서 생성·편집
- `xlsx` — 엑셀 생성·수식·차트
- `pptx` — 프레젠테이션
- `pdf` — PDF 읽기·병합·양식 채우기

### 오픈 표준
Agent Skills 형식은 **오픈 표준(agentskills.io)** 으로 공개되어, Claude 외에 여러 AI 코딩 도구에서도 같은 `SKILL.md` 폴더를 읽을 수 있다.
필수 요소는 `name`, `description`, 그리고 마크다운 본문뿐이다.

## 8. 좋은 스킬 작성법

### ✅ description은 "무엇 + 언제"
```yaml
# 나쁜 예
description: PDF 처리 도구

# 좋은 예
description: PDF에서 텍스트·표를 추출하고, 양식을 채우고, 여러 PDF를 합칠 때 사용. 사용자가 PDF, 양식, 문서 추출을 언급하면 사용.
```
- 3인칭 서술로, **사용자가 실제로 할 법한 말**("이 음성 받아써줘", "냉장고에 뭐 있지")을 트리거 예시로 넣는다.
- 쓰면 안 되는 경우도 적는다. (예: xlsx 스킬의 "Word 문서가 결과물이면 쓰지 말 것")

### ✅ 본문은 짧고 명확하게
- `SKILL.md` 본문은 **500줄 이내**를 목표로 한다. 호출된 뒤로는 매 턴 컨텍스트를 차지하기 때문이다.
- Claude가 이미 잘 아는 내용은 빼고, **이 프로젝트만의 규칙과 함정(gotcha)** 위주로 쓴다.
- 긴 참고 자료는 `reference.md` 등으로 빼고 본문에서 링크한다. 참조는 **한 단계 깊이**까지만.

### ✅ 반복 작업은 스크립트로
- 매번 Claude가 코드를 새로 짜게 하지 말고 `scripts/`에 넣어 두고 실행만 시킨다. 결과가 일정해지고 토큰도 아낀다.
  (예: whisper 스킬의 `scripts/transcribe.sh`)

### ✅ 부작용 있는 작업은 수동 전용
```yaml
---
name: deploy
disable-model-invocation: true
allowed-tools: Bash(git *), Bash(npm run build)
---
```

### ✅ 테스트하기
- 스킬을 켠 상태/끈 상태로 같은 요청을 새 세션에서 돌려 비교한다.
- 의도한 요청에서 **제대로 호출되는지**, 엉뚱한 요청에서 **호출되지 않는지** 둘 다 확인한다.

### ⚠️ 보안 주의
- 스킬은 **프로그램 설치와 같다.** 출처를 모르는 스킬은 스크립트까지 전부 읽어 보고 설치한다.
- 외부 URL에서 내용을 받아오는 스킬은 데이터 유출 위험이 있다.
- API 키는 스킬 본문이나 스크립트에 적지 말고 `.env` 환경변수로 읽게 한다. (예: whisper 스킬의 `OPENAI_API_KEY`)

## 9. 이 저장소에서 쓰는 스킬 예시

`.claude/skills/`에 설치된 스킬들:

| 스킬 | 하는 일 | 참고 포인트 |
| --- | --- | --- |
| `yt-dlp` | 유튜브 자막·음성·메타데이터 다운로드 | 자막이 없으면 `whisper`로 넘기는 **스킬 연계** |
| `whisper` | 음성 → 텍스트 받아쓰기 | 스크립트 동봉, 키는 `.env` |
| `recipe` | 냉장고 재료 JSON 관리 + 레시피 추천·저장 | 상태를 대화가 아닌 **폴더 파일**에 저장 |
| `quick-recipe` | 15분 레시피 문서 작성 | 기존 문서 포맷을 그대로 재현하는 **규칙형** 스킬 |
| `single-react-dev` | CDN React 단일 `index.html` 웹앱 | 버전 고정 등 함정 정리 |
| `single-server-specialist` | 단일 `server.js` Node 백엔드 | 파일 구조 순서까지 규정 |
| `docx` / `xlsx` / `pdf` / `hwpx` | 문서 파일 생성·편집 | `allowed-tools`, `${CLAUDE_SKILL_DIR}` 활용 |

실제 흐름 예시 (week-5 수업):
1. "이 유튜브 영상 정리해줘" → `yt-dlp` 스킬 자동 호출 → `meta.json`, `video.ko.vtt`, `transcript.md` 생성
2. 자막 품질이 부족하면 → `whisper` 스킬로 `audio.mp3` 받아쓰기 → `transcript-whisper.md` 생성

## 10. 한 장 요약

```
스킬 = 폴더 + SKILL.md (+ 스크립트/참고자료)

평소:     이름 + 설명만 기억        (가볍다)
요청 매칭: SKILL.md 본문 로드       (필요할 때만)
필요 시:   scripts/, reference.md   (더 필요할 때만)

설치 위치: ~/.claude/skills (개인)  |  .claude/skills (프로젝트)
실행:     자동(설명 매칭)  또는  /스킬명 인자
핵심:     description = 무엇을 + 언제
```
