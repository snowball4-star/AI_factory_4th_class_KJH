# 냉장고 재료 → 레시피 추천기

냉장고 재고를 **재료 1개당 JSON 파일 1개**로 관리하고, 그 폴더 전체를 읽어 지금 만들 수 있는 요리를 추천한 뒤, 선택된 레시피를 **markdown 파일로 저장**한다.

재료 파일은 사람이 직접 열어 고칠 수 있는 평문 JSON이고, 재고 상태는 오직 이 폴더에만 존재한다. **대화 기억이 아니라 항상 폴더를 다시 읽어서** 판단한다 — 사용자가 세션 밖에서 파일을 지우거나 고쳤을 수 있다.

## 📁 폴더 구조

| 대상 | 경로 |
| --- | --- |
| 재료 JSON (재료당 1개) | `week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬/fridge/ingredients/<재료명>.json` |
| 생성된 레시피 | `week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬/fridge/recipes/<YYYY-MM-DD>-<요리명>.md` |
| 재료 기입 웹 UI | `week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬/index.html` |
| 기입 UI 백엔드 | `week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬/server.js` — 파일 쓰기를 담당 |
| 스킬 본문 제출본 | `week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬/SKILL.md` — 이 파일과 같은 내용 |

- 이 문서에서 `fridge/…` 로 시작하는 경로는 모두 위 표의 **퀘스트 폴더 기준 상대 경로**다.
- 파일명은 **재료명 그대로** 쓴다 (`대파.json`, `모짜렐라치즈.json`). 공백은 `_`로 바꾸고, `/ \ : * ? " < > |` 는 제거한다.
- 같은 재료를 다시 넣으면 **새 파일을 만들지 않고 기존 파일을 갱신**한다. 파일이 두 개로 갈라지면 재고가 두 번 계산된다.
- 이 스킬은 `.claude/skills/recipe/SKILL.md` 에 설치돼 있고, 같은 내용의 제출본이 퀘스트 폴더에 있다.
  **스킬 내용을 고치면 두 파일을 함께 갱신**한다 — 한쪽만 고치면 제출본과 실제 동작이 어긋난다.
- 폴더가 없으면 만든다. 폴더가 비어 있으면 그것은 "냉장고가 비었다"는 정상 상태다.

## 🧾 재료 JSON 스키마

```json
{
  "id": "대파",
  "name": "대파",
  "category": "채소",
  "quantity": 2,
  "unit": "대",
  "storage": "냉장",
  "purchasedOn": "2026-09-10",
  "expiresOn": "2026-09-20",
  "note": "반 단 남음",
  "updatedAt": "2026-09-13T21:04:00+09:00"
}
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `id` | ✅ | 확장자를 뺀 파일명과 **정확히 일치**해야 한다 |
| `name` | ✅ | 화면에 보여줄 재료 이름 |
| `category` | ✅ | `채소` `과일` `육류` `해산물` `유제품` `달걀` `곡물·면` `양념` `가공식품` `음료` `기타` 중 하나 |
| `quantity` | ✅ | 숫자. 정확한 수량을 모르면 `1`을 쓰고 `note`에 `대략`이라 적는다 |
| `unit` | ✅ | `개` `g` `ml` `대` `쪽` `봉` `팩` `줌` 등 |
| `storage` | ✅ | `냉장` `냉동` `실온` |
| `purchasedOn` | | `YYYY-MM-DD`. 모르면 오늘 날짜 |
| `expiresOn` | | `YYYY-MM-DD`. 사용자가 말하지 않으면 **추측해서 넣지 말고 비운다** (`null`) |
| `note` | | 손질 상태·브랜드·남은 양 메모 |
| `updatedAt` | ✅ | 쓸 때마다 갱신하는 ISO 8601 시각 |

- **JSON은 UTF-8, 2칸 들여쓰기, 마지막 줄바꿈 포함**으로 쓴다. 주석은 넣지 않는다 (JSON에 주석은 없다).
- 스키마에 없는 필드는 넣지 않는다. 대신 `note`에 문장으로 적는다.

## 🚦 모드 판별

`/recipe` 뒤에 오는 말로 무엇을 할지 정한다. 애매하면 되묻지 말고 **재고를 먼저 읽고** 가장 그럴듯한 모드로 진행한 뒤, 다른 모드였다면 어떻게 부르는지 한 줄로 알려준다.

| 입력 | 모드 |
| --- | --- |
| `/recipe` (인자 없음) | **3. 레시피 추천** |
| `/recipe 계란 6개, 대파 2대` · `/recipe 추가 …` | **1. 재료 추가** |
| `/recipe 목록` · `/recipe 냉장고` | **2. 재고 조회** |
| `/recipe 김치찌개` (요리 이름) | **4. 레시피 생성·저장** |
| `/recipe 소진 대파` · `/recipe 대파 다 씀` | **5. 재료 차감·삭제** |

## 1. 재료 추가·갱신

1. `fridge/ingredients/` 폴더를 먼저 읽어 **이미 있는 재료인지 확인**한다.
2. 사용자 문장을 재료 단위로 쪼갠다. `계란 6개, 대파 2대, 삼겹살 300g` → 3개.
3. 재료마다 파일 하나를 쓴다.
   - **새 재료** → 파일 생성. `purchasedOn`은 오늘.
   - **있던 재료** → `quantity`를 **더하고** `updatedAt`을 갱신한다. 단위가 다르면(`300g` vs `2팩`) 임의 환산하지 말고 사용자에게 어느 단위로 합칠지 묻는다.
4. 마지막에 **무엇을 새로 만들고 무엇을 갱신했는지** 표로 보고한다.

수량·단위를 말해주지 않았으면 (`계란 있어`) `quantity: 1`, 단위는 그 재료에 자연스러운 것으로 넣고, 표 보고에 `수량 미상 — 필요하면 알려줄 것`이라고 표시한다. 되묻느라 작업을 멈추지 않는다.

## 2. 재고 조회

`fridge/ingredients/*.json`을 전부 읽어 표로 보여준다. **카테고리 순 → 유통기한 임박 순**으로 정렬한다.

| 재료 | 수량 | 보관 | 유통기한 | 상태 |
| --- | --- | --- | --- | --- |
| 대파 | 2대 | 냉장 | 2026-09-20 | D-7 |
| 두부 | 1모 | 냉장 | 2026-09-14 | ⚠️ D-1 |
| 삼겹살 | 300g | 냉동 | — | |

- `expiresOn`이 오늘로부터 **2일 이내면 `⚠️`**, **지났으면 `❌ 기한 경과`**를 붙이고 표 아래에 따로 한 줄 경고한다.
- `expiresOn`이 없으면 `—`. 임의로 채우지 않는다.

## 3. 레시피 추천 (기본 모드)

1. `fridge/ingredients/` 전체를 읽는다. **비어 있으면** 추천하지 말고 재료를 넣는 두 가지 방법(`/recipe 계란 6개…`, 웹 UI)을 안내하고 끝낸다.
2. **후보 3개**를 제안한다. 각 후보는 이렇게 한 덩어리로 쓴다:

   ```
   ### 1. 대파 계란 볶음밥 (12분 · 쉬움)
   - **쓰는 재료**: 대파 1대, 계란 3개, 찬밥 1공기
   - **부족한 재료**: 없음
   - **왜 이걸**: 두부(D-1)를 빼면 오늘 가장 급한 재료가 대파고, 이 조합이 대파를 가장 많이 쓴다.
   ```

3. 후보 구성 규칙:
   - **최소 1개는 "부족한 재료 없음"** — 지금 당장 만들 수 있는 것이 하나는 있어야 한다.
   - **최소 1개는 유통기한이 가장 임박한 재료를 주재료로** 쓴다.
   - 나머지 1개는 재료 1~2개만 더 사면 되는 것으로 폭을 넓힌다. 부족한 재료는 반드시 명시한다.
   - 소금·간장·설탕·식용유·후추 같은 **기본 양념은 냉장고에 있다고 가정**하고 부족 재료로 세지 않는다. 다만 레시피 문서의 재료표에는 적는다.
4. **없는 재료를 있다고 쓰지 않는다.** 폴더에 없으면 부족 재료다.
5. 어느 것을 만들지 사용자가 고르면 → **4. 레시피 생성·저장**으로 넘어간다.

## 4. 레시피 생성 · markdown 저장

`fridge/recipes/<YYYY-MM-DD>-<요리명>.md`로 저장한다. 같은 날 같은 요리를 또 만들면 `-2`를 붙인다.

문체와 밀도는 **`quick-recipe` 스킬과 동일**하게 간다: 평서형 `~한다` 종결, `적당히` 금지(모든 분량은 숫자), 조리 단계마다 **누적 경과 시간**, 모든 지시에 이유를 붙인다. 15분 제한은 이 스킬에는 없다.

```markdown
# {요리명} ({N}분)

{냉장고에 있던 무엇을 쓰려고 고른 요리인지 2~3문장.}

- **소요 시간**: {N}분 (준비 {a}분 + 조리 {b}분)
- **분량**: {1인분 | 2인분}
- **난이도**: {아주 쉬움 | 쉬움 | 보통}
- **생성일**: {YYYY-MM-DD}

## 냉장고에서 쓰는 재료

| 재료 | 필요량 | 보유량 | 상태 |
| --- | --- | --- | --- |
| 대파 | 1대 | 2대 | ✅ |
| 두부 | 1/2모 | 1모 | ⚠️ D-1, 오늘 소비 |

## 더 필요한 재료

| 재료 | 필요량 | 메모 |
| --- | --- | --- |
| 청양고추 | 2개 | 없으면 생략, 대신 고춧가루 1작은술 |

> 부족한 재료가 없으면 이 섹션 대신 `모든 재료가 냉장고에 있다.` 한 줄만 쓴다.

## 만드는 법

1. **{단계명} (0분)** — {행동과 그 이유.}
   … 5~7단계, 마지막 단계의 분 = 제목의 분 …

## 성공 포인트

- **{명령형 단언.}** {어기면 어떻게 되는지.}
  … 3~5개 …

## 남은 재료 활용

- {이 요리를 하고도 남는 재료로 뭘 더 할 수 있는지 2~3줄.}
```

저장한 뒤:

1. **저장 경로를 클릭 가능한 링크로 알려준다.**
2. 사용자가 **"만들었다 / 해먹었다"고 하면** 그때 재고를 차감한다 (모드 5). 레시피를 저장한 것만으로는 재고를 건드리지 않는다 — 저장은 계획이고 차감은 실행이다.

## 5. 재료 차감 · 삭제

- 수량을 말하면 (`대파 1대 썼어`) 그만큼 빼고 `updatedAt`을 갱신한다.
- 다 썼으면 (`대파 다 씀`, `소진`) **파일을 삭제**한다. `quantity: 0`으로 남겨두지 않는다 — 빈 껍데기가 쌓이면 추천이 흐려진다.
- 차감 결과 `quantity`가 0 이하가 되면 삭제한다.
- 삭제·차감한 목록을 표로 보고한다.

## 🖥 재료 기입 웹 UI

`index.html`(화면) + `server.js`(파일 쓰기) 로 된 재료 기입 앱이다. 대화로 재료를 부르는 대신 폼으로 넣고 싶을 때 쓴다. 브라우저는 자기 서버의 `/api` 만 부르고, `fridge/ingredients/<재료명>.json` 을 쓰고 지우는 일은 전부 `server.js` 가 한다.

```bash
cd "week-4/project/퀘스트 3. 냉장고 재료 기반 레시피 제작 스킬"
npm install        # 최초 1회 (express)
npm start          # → http://localhost:3000
```

- 저장 폴더는 **`server.js` 안에 고정**돼 있어서 사용자가 폴더를 고를 필요가 없다. 다른 곳에 쓰고 싶으면 `FRIDGE_DIR` 환경변수로 덮어쓴다.
- 포트가 이미 쓰이고 있으면 `PORT=3500 npm start` 처럼 바꾼다 (week-4 의 다른 앱들도 3000 을 쓴다).
- API 는 `GET /api/ingredients`, `POST /api/ingredients`, `DELETE /api/ingredients/:id`, `GET /api/config` 넷뿐이다.
- **`index.html` 을 파일로 직접 열면 저장되지 않는다.** 그때는 화면에 서버를 켜라는 안내가 뜬다.
- 재료 이름은 서버에서 다시 한 번 걸러 파일명으로 만든다 — `../` 같은 경로 문자가 섞여 있으면 저장을 거부한다.
- 이 UI 와 서버가 쓰는 스키마는 위 표와 **정확히 같다**. 스키마를 고치면 `index.html` 의 `makeIngredient()` 와 `server.js` 의 `normalize()` 를 **함께** 고친다.

## ✅ 저장 전 체크리스트

- [ ] 재료 파일명(확장자 제외) == JSON의 `id`
- [ ] 같은 재료가 두 파일로 갈라지지 않았다
- [ ] 레시피의 "냉장고에서 쓰는 재료"에 적힌 것이 **전부 실제로 폴더에 있다**
- [ ] 필요량 ≤ 보유량. 넘으면 "더 필요한 재료"로 옮긴다
- [ ] 마지막 조리 단계의 분 = 제목의 분 = 소요 시간 불릿의 분
- [ ] 재료표의 모든 재료가 조리 순서에 등장한다 (그 반대도)
- [ ] 레시피 파일이 `fridge/recipes/`에 저장됐고 경로를 사용자에게 알렸다
